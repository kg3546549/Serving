# 장비 티어·레벨·합성·증강 구현 명세

> 기준: 2026년 6월 19일 현재 코드

## 1. 성장 구조

| 성장 축 | 범위 | 효과 |
|---|---:|---|
| 플레이어 레벨 | 1~10 | 상점 티어 확률 변경, 인프라 확장 선택 발생 |
| 장비 티어 | 1~5 | 가격, 희귀도, 역할 복잡도 |
| 장비 성급 | 1~3성 | 동일 장비 합성에 따른 처리 성능과 증강 |

플레이어 레벨이 오르면 팝업에서 `LINK CAPACITY` 또는 `BOARD SIZE` 중 하나를 선택한다. 장비 티어는 합성으로 바뀌지 않는다.

서버, DB, 로드밸런서는 보드 역할 슬롯에 직접 배치한다. Queue, Cache, Security, Storage 계열은 현재 보유 시 아키텍처 성능을 보정하는 패시브 장비로 동작한다.

첫 웨이브는 최소 경로를 만들 수 있어야 하므로 최초 상점만 다음 5개를 고정 제공한다.

```text
EC2 App Server
RDS Primary DB
API Gateway
SQS Message Queue
Apache Web Server
```

이후 상점은 플레이어 레벨 확률표를 사용한다.

## 5. 보유 장비와 합성

- 보유 장비 슬롯: 8칸 고정
- 배치한 장비도 보유 슬롯에 남으며 `ACTIVE`로 표시
- 같은 종류와 같은 성급 장비 3개를 모으면 즉시 자동 합성
- 1성 3개 → 2성 1개
- 2성 3개 → 3성 1개
- 배치 중인 장비가 합성 재료에 포함되면 합성 장비가 해당 역할과 위치를 우선 승계

성급과 티어에 따라 서버 동시 처리량, Queue, DB 처리량, 응답 시간이 보정된다.

## 6. 역할별 증강

합성 직후 세 가지 증강 중 하나를 선택한다.

| 역할 | 일반 증강 예시 | 레어 증강 예시 |
|---|---|---|
| 서버 | RAM 증설, CPU 증설 | Auto Scaler |
| DB | 쿼리 최적화, DB 용량 증설 | DB Sharding, DAX |
| 로드밸런서 | 백엔드 슬롯, Health Check | 지능형 라우팅 |
| Queue | Consumer 증설 | 파티션 확장 |
| Cache | Cache Hit 향상 | DAX |
| Security | 보안 규칙 최적화 | DDoS Scrubbing |
| Storage | 처리량 증설 | 고성능 Storage I/O |

레어 증강이 세 번째 선택지에 등장할 확률:

- 2성 합성: 5%
- 3성 합성: 15%
