# 오토배틀러 상점·레벨·장비 합성 설계

> 문서 상태: 향후 확장 기획. 상점, 리롤, 레벨, 장비 합성은 현재 코드에 구현되지 않았다.
>
> 목표: 처리한 요청으로 돈을 벌고, 레벨업·리롤·장비 구매·합성 중 어디에 투자할지 선택하는 아키텍처 오토배틀러 구조

---

## 1. 성장 축은 세 가지로 분리한다

게임에서 `레벨`이라는 말을 하나로 사용하면 혼란이 생긴다.

| 성장 축 | 범위 | 의미 |
|---|---|---|
| 플레이어 레벨 | 1~10 | 상점 티어 확률과 설치 가능한 장비 수 |
| 장비 티어 | 1~5 | 해당 장비 설계의 희귀도·가격·기능 복잡도 |
| 장비 성급 | 1~3성 | 같은 장비를 모아 합성한 강화 단계 |

예:

```text
플레이어 레벨 7
3티어 장비인 문어 서버
2성으로 합성된 상태
```

장비 티어는 합성으로 변하지 않는다.

```text
1티어 몽글이 3개
→ 1티어 몽글이 2성
```

```text
1티어 몽글이 3성
≠ 3티어 장비
```

# 2. 한 스테이지의 경제 흐름

```text
요청 처리
→ 요청당 $1 이상 획득
→ 상점에서 장비 구매
→ 같은 장비 합성
→ 장비 설치 또는 보관
→ 다음 웨이브 처리
→ 레벨업 또는 리롤
```

플레이어는 항상 세 가지 중 하나를 선택한다.

### 즉시 전력

현재 상점의 장비를 구매한다.

### 미래 투자

플레이어 레벨을 올려 고티어 장비 확률과 설치 한도를 높인다.

### 조합 탐색

리롤하여 필요한 장비 복제본이나 다른 시스템을 찾는다.

이 세 선택이 돈의 핵심 사용처다.

# 3. 상점 구조

## 3.1 상점 카드 10개

준비 단계마다 설비 카드 10개를 표시한다.

```text
┌────┬────┬────┬────┬────┐
│ 01 │ 02 │ 03 │ 04 │ 05 │
├────┼────┼────┼────┼────┤
│ 06 │ 07 │ 08 │ 09 │ 10 │
└────┴────┴────┴────┴────┘
```

각 카드에는 최소 정보만 표시한다.

- 캐릭터 아이콘
- 이름
- 티어 색상
- 가격
- 현재 보유 수
- 합성까지 필요한 개수

카드를 길게 누르거나 `?`를 눌러야 상세 역할과 실제 아키텍처 개념을 보여 준다.

## 3.2 상점 갱신

- 스테이지 시작: 무료 상점 1회
- 각 웨이브 종료: 무료 갱신 1회
- 수동 리롤: 기본 `$8`
- 같은 준비 단계에서 연속 리롤: `$8 → $10 → $12 → ...`
- 다음 웨이브 준비 단계가 되면 다시 `$8`

10칸 상점은 일반적인 5칸 상점보다 선택지가 많으므로 리롤 비용도 높게 잡는다.

## 3.3 카드 고정

최대 3장을 핀으로 고정할 수 있다.

- 리롤해도 고정 카드 유지
- 웨이브가 바뀌어도 유지
- 구매하거나 고정을 해제하면 슬롯 반환

필요한 복제본을 기다리는 전략을 가능하게 한다.

## 3.4 동일 카드 중복

한 상점에서 같은 장비가 여러 장 나올 수 있다.

합성이 핵심이므로 중복 방지 기능은 사용하지 않는다.

# 4. 플레이어 레벨 1~10

## 4.1 레벨이 제공하는 것

플레이어 레벨을 올리면 다음 두 가지가 변한다.

1. 상점에서 높은 티어 장비가 나올 확률 증가
2. 보드에 동시에 설치할 수 있는 장비 수 증가

## 4.2 설치 가능 수

입구와 출구처럼 스테이지에서 기본 제공되는 시설은 제한에 포함하지 않는다.

| 플레이어 레벨 | 설치 가능 장비 |
|---:|---:|
| 1 | 3 |
| 2 | 4 |
| 3 | 5 |
| 4 | 6 |
| 5 | 7 |
| 6 | 8 |
| 7 | 9 |
| 8 | 10 |
| 9 | 11 |
| 10 | 12 |

레벨업은 단순 상점 확률뿐 아니라 실제 아키텍처 크기를 키운다.

## 4.3 경험치

- 웨이브 완료: 무료 XP `+2`
- XP 구매: `$4`를 사용해 XP `+4`
- 상단 레벨 버튼을 누르면 여러 번 구매 가능

## 4.4 필요 XP

| 레벨 | 다음 레벨까지 필요 XP |
|---:|---:|
| 1→2 | 4 |
| 2→3 | 8 |
| 3→4 | 12 |
| 4→5 | 16 |
| 5→6 | 24 |
| 6→7 | 32 |
| 7→8 | 44 |
| 8→9 | 60 |
| 9→10 | 80 |

초반에는 빠르게 오르고 후반에는 장비 구매와 레벨업 사이에서 큰 선택을 요구한다.

## 4.5 캠페인별 레벨 상한

초기 스테이지부터 5티어 장비가 등장하지 않도록 상한을 둔다.

| 캠페인 스테이지 | 최대 플레이어 레벨 |
|---:|---:|
| 1 | 3 |
| 2 | 4 |
| 3 | 5 |
| 4 | 6 |
| 5 | 7 |
| 6 | 8 |
| 7 | 9 |
| 8~10 | 10 |

후반 스테이지에서는 처음부터 일부 XP를 제공해 낮은 레벨 반복 구간을 줄일 수 있다.

# 5. 레벨별 장비 티어 확률

각 상점 슬롯은 아래 확률로 티어를 먼저 결정하고, 해당 티어에서 해금된 장비 하나를 선택한다.

| 플레이어 레벨 | 1티어 | 2티어 | 3티어 | 4티어 | 5티어 |
|---:|---:|---:|---:|---:|---:|
| 1 | 70% | 30% | 0% | 0% | 0% |
| 2 | 60% | 35% | 5% | 0% | 0% |
| 3 | 50% | 35% | 15% | 0% | 0% |
| 4 | 40% | 35% | 22% | 3% | 0% |
| 5 | 30% | 35% | 27% | 8% | 0% |
| 6 | 22% | 30% | 33% | 14% | 1% |
| 7 | 15% | 25% | 35% | 21% | 4% |
| 8 | 10% | 20% | 33% | 29% | 8% |
| 9 | 7% | 17% | 30% | 32% | 14% |
| 10 | 5% | 15% | 30% | 30% | 20% |

레벨 10에서도 5티어만 나오지 않는다.

저티어 장비는 합성과 기본 아키텍처 구성에 계속 필요하기 때문이다.

## 확률 표시

레벨 버튼을 누르면 다음 레벨의 티어 확률을 미리 볼 수 있다.

```text
현재 Lv.6
3티어 33%
4티어 14%
5티어 1%

Lv.7 도달 시
3티어 35%
4티어 21%
5티어 4%
```

플레이어가 레벨업의 가치를 이해할 수 있어야 한다.

# 6. 장비 티어 1~5

티어는 장비의 기본 희귀도와 기능 복잡도를 의미한다.

## 1티어: 기초 시설

**가격 기준:** `$5`

- 몽글이 범용 서버
- Static Server
- 기본 Firewall
- 기본 Metrics
- 기본 Queue Buffer

특징:

- 저렴함
- 합성이 쉬움
- 단일 기능
- 후반에도 보조 시설로 사용

## 2티어: 확장 시설

**가격 기준:** `$12`

- 토끼 서버
- 문어 서버
- L4 Load Balancer
- App Cache
- Rate Limiter
- Connection Pool

특징:

- 아키텍처 분기 시작
- 특정 병목에 명확한 효과

## 3티어: 전문 시스템

**가격 기준:** `$25`

- 해파리 I/O 서버
- 붕붕이 Worker
- L7 Load Balancer
- WAF
- CDN
- Read Replica
- Message Queue

특징:

- 요청 종류에 따른 경로 설계
- 서버 전문화
- 중반 핵심 장비

## 4티어: 고급 운영 시스템

**가격 기준:** `$50`

- 대장장이 Compute Server
- 장인 Microservice
- Auto Scaling Controller
- Circuit Breaker
- Outlier Detection
- Kafka / Stream
- Origin Shield

특징:

- 장애와 대규모 Burst 대응
- 단독보다 기존 시스템과 조합할 때 강함

## 5티어: 전설 시스템

**가격 기준:** `$90`

- 드래곤 GPU 서버
- 구름콩 Serverless Cluster
- Global Load Balancer
- Multi-Zone Controller
- DDoS Scrubbing Center
- Database Sharding Controller

특징:

- 매우 강한 특정 효과
- 높은 구매 비용
- 모든 상황의 정답은 아님
- 잘못 배치하면 가격 대비 효율이 낮음

# 7. 장비 성급 1~3성

장비의 개별 레벨은 `성급`으로 표현하는 것이 가장 직관적이다.

## 7.1 합성 규칙

```text
같은 1성 장비 3개
→ 2성 장비 1개
```

```text
같은 2성 장비 3개
→ 3성 장비 1개
```

따라서 3성 하나에는 같은 장비 1성 9개가 필요하다.

## 7.2 설치하지 않아도 합성 가능

장비는 다음 위치 어디에 있어도 합성 대상으로 계산한다.

- 보드에 설치
- 벤치에 보관
- 상점에서 방금 구매

예:

```text
보드 몽글이 1개
벤치 몽글이 1개
상점 몽글이 1개 구매

→ 보드의 몽글이가 자동으로 2성
```

## 7.3 합성 우선순위

1. 보드에 설치된 장비
2. 가장 먼저 구매한 벤치 장비
3. 새 카드

플레이어가 의도한 배치가 사라지지 않게 설치 장비를 강화한다.

## 7.4 성급별 일반 강화

| 성급 | 필요 1성 개수 | 처리량 | 동시성 | Queue·용량 | 추가 효과 |
|---:|---:|---:|---:|---:|---|
| 1성 | 1 | 100% | 100% | 100% | 기본 |
| 2성 | 3 | 180% | 150% | 150% | 고유 효과 강화 |
| 3성 | 9 | 400% | 250% | 200% | 시그니처 기능 |

9배 가격에 정확히 9배 성능을 주지는 않는다.

성급의 핵심 이점은 제한된 설치 슬롯 하나로 더 높은 성능을 내는 것이다.

## 7.5 3성 시그니처 효과

단순 수치 증가만 있으면 장비 캐릭터성이 약하다.

### 몽글이 3성

처리 완료 시 15% 확률로 다음 일반 요청을 즉시 완료.

### 토끼 3성

Queue가 비어 있으면 첫 요청을 처리 시간 없이 즉시 반환.

### 문어 3성

동시에 잡은 요청이 많을수록 처리 속도 증가.

### Load Balancer 3성

매 요청마다 가장 빠른 서버 경로를 예측해 전달.

### Cache 3성

인기 요청 하나를 자동으로 고정해 만료되지 않게 유지.

### Queue 3성

가득 차기 직전에 임시 버퍼를 한 번 생성.

### CDN 3성

새 정적 요청의 첫 응답도 일부 Edge에서 즉시 처리.

### Circuit Breaker 3성

장애 경로를 차단한 뒤 정상 경로에 짧은 처리량 버프 제공.

# 8. 장비별 합성 강화 방식

모든 장비에 처리량이라는 수치를 억지로 적용하지 않는다.

| 장비 종류 | 2성 강화 | 3성 강화 |
|---|---|---|
| 처리 서버 | 처리량·동시 슬롯 증가 | 시그니처 처리 방식 |
| Load Balancer | 최대 경로·분배 속도 증가 | 예측 라우팅 |
| Firewall/WAF | 검사량·정확도 증가 | 오탐 감소·범위 규칙 |
| Cache/CDN | 용량·Hit 속도 증가 | 인기 콘텐츠 자동 고정 |
| Queue | 용량·유입 속도 증가 | 임시 Overflow Buffer |
| DB/Replica | 연결·쿼리 처리 증가 | 장애 시 자동 승격 |
| Metrics | 관측 범위 증가 | 다음 웨이브 병목 예측 |
| Auto Scaling | 생성 속도·최대 복제 증가 | Warm Instance 유지 |

# 9. 벤치와 설치 규칙

## 벤치

- 기본 10칸
- 플레이어 레벨 5에서 12칸
- 플레이어 레벨 8에서 14칸
- 합성 직전 장비를 보관하는 공간

벤치가 가득 차면:

- 합성되는 구매는 허용
- 새로운 단독 장비 구매는 불가

## 설치 장비

- 플레이어 레벨에 따라 설치 한도 증가
- 같은 장비 여러 대 설치 가능
- 2성·3성도 설치 슬롯은 하나만 사용

## 판매

| 장비 | 판매 금액 |
|---|---:|
| 1성 | 구매 가격 100% |
| 2성 | 사용된 3개 가격 100% |
| 3성 | 사용된 9개 가격 100% |

초기 설계에서는 판매 손실을 없앤다.

상점 조합을 실험하는 재미를 막지 않기 위해서다.

아키텍트 난이도에서는 80% 환불을 적용할 수 있다.

# 10. 장비 카드 풀

싱글 플레이 게임이므로 다른 플레이어와 장비 수량을 공유하지 않는다.

그러나 고티어 3성을 지나치게 쉽게 만들지 않도록 티어별 등장 가중치와 카드 수를 둔다.

| 티어 | 장비 종류 수 권장 | 같은 장비 최대 카드 수 |
|---:|---:|---:|
| 1 | 8~10종 | 24 |
| 2 | 8~10종 | 18 |
| 3 | 7~9종 | 14 |
| 4 | 6~8종 | 10 |
| 5 | 5~7종 | 9 |

5티어 3성은 같은 카드 9개를 모두 찾아야 하므로 매우 희귀한 목표가 된다.

## 카드 반환

- 장비 판매 시 카드가 풀로 돌아감
- 스테이지 재시작 시 전체 초기화
- 상점에서 구매하지 않은 카드는 리롤 시 풀로 복귀

# 11. 지나친 리롤 운을 완화하는 장치

## 카드 핀

필요한 카드 최대 3개 보존.

## 합성 근접 표시

```text
몽글이 5/9
다음 2성까지 1개
3성까지 4개
```

## 보장 상점

보스 웨이브 직전 한 번:

- 현재 보유 장비 중 하나의 복제본 최소 1장 등장
- 4티어 이상은 보장 대상에서 제외하거나 높은 비용 요구

## 선택 보상

특정 웨이브 클리어 시 세 장 중 하나 선택.

```text
몽글이
Load Balancer
Cache
```

## 지나친 천장 시스템은 피한다

원하는 장비가 매번 확정되면 리롤과 조합의 의미가 사라진다.

# 12. 상단 상태 바

상단에는 텍스트를 최소화하고 다음 정보만 상시 표시한다.

```text
┌─────────────────────────────────────────────────────────────┐
│ Stage 4-3  ⏱ 00:42   $ 186   Lv.6  18/32XP   520/600 RPM │
└─────────────────────────────────────────────────────────────┘
```

## 표시 항목

### Stage

```text
4-3
```

- 캠페인 Stage 4
- 세 번째 웨이브

### 시간

- 현재 웨이브 남은 시간
- 보스 요청 제한 시간

### 돈

- 현재 사용 가능 코인
- 요청 완료 시 숫자가 통통 증가

### 플레이어 레벨

- 현재 레벨
- XP 진행
- 클릭하면 다음 레벨 확률 표시
- `+4 XP / $4` 버튼

### 현재 처리량

두 값을 함께 보여 준다.

```text
실제 처리 520 RPM
현재 유입 600 RPM
```

간단 표시:

```text
520 / 600 RPM
```

이 값이 타워디펜스의 공격력과 가장 유사하다.

그러나 처리량만 높아도 Queue가 너무 길면 지연 문제가 생긴다.

RPM 표시 옆의 작은 색상:

- 민트: 처리량 > 유입량
- 노랑: 비슷함
- 빨강: 처리량 < 유입량

### 서비스 안정도

하트 또는 서버 얼굴로 표시한다.

- 정상 처리율
- Timeout
- 데이터 유실

MVP에서는 처리량과 돈만 표시하고 안정도는 도움말 안에 둘 수 있다.

# 13. 코인 애니메이션

## 요청 하나 처리

```text
응답이 출구 도착
→ 작은 $1 동전 생성
→ 통통 튀며 상단 돈 아이콘으로 이동

```

## 대량 처리

초당 10개 이하:

- 요청별 동전 표시

초당 10개 초과:

- 동전 일부만 개별 표시

```text

+$24
```

수익 계산은 여전히 요청별로 한다.

## 보스 요청

- 큰 동전 또는 보상 상자
- `$50`
- 특정 장비 선택권
- 무료 리롤권

# 14. 돈의 주요 사용처

권장 비율:

| 사용처 | 일반적인 소비 비율 |
|---|---:|
| 장비 구매·합성 | 45~60% |
| 플레이어 레벨업 | 20~35% |
| 리롤 | 10~20% |
| 긴급 복구·재배치 | 0~10% |

리롤이 전체 소비의 대부분이 되면 설계 게임보다 운 게임이 된다.

레벨업만 하는 것이 항상 정답이어도 안 된다.

# 15. 레벨업과 리롤의 선택

## 레벨업이 좋은 상황

- 현재 장비로 웨이브를 안정적으로 처리
- 설치 한도가 부족
- 다음 티어 장비가 필요
- 장기적으로 강한 구성을 노림

## 리롤이 좋은 상황

- 서버 OFF가 임박
- 같은 장비 1개만 더 있으면 2성
- 현재 병목에 대응하는 시스템이 없음
- 보스 웨이브가 바로 다음

## 장비 구매가 좋은 상황

- 현재 상점에 필요한 카드가 있음
- 합성 직전
- 현재 웨이브가 위험

상단 레벨 버튼과 하단 리롤 버튼에 현재 추천을 직접 표시하지 않는다.

플레이어가 보드 상태를 보고 판단하도록 한다.

# 18. 밸런스 위험과 대응

## 성공할수록 돈이 더 늘어나는 스노우볼

문제:

강한 플레이어가 더 많은 요청을 처리해 더 빠르게 강해짐.

대응:

- 웨이브당 최대 유입량 고정
- 초과 처리량은 코인을 무한 생성하지 않음
- 실패 플레이어에게 최소 운영 지원금
- 다음 웨이브 난이도는 수익이 아니라 스테이지 기준으로 결정

## 10칸 상점으로 합성이 너무 쉬움

대응:

- 티어별 장비 종류 수 확보
- 고티어 카드 풀 제한
- 리롤 비용 누적 증가
- 3성은 9개 요구

## 고티어가 무조건 강함

대응:

- 5티어는 특정 역할 특화
- 높은 가격
- 설치 준비 시간
- 잘못된 요청에는 낮은 효율
- 저티어 3성이 고티어 1성보다 강할 수 있음

권장 전력 관계:

```text
1티어 3성 ≈ 3티어 2성
2티어 3성 ≈ 4티어 2성
5티어 1성은 강하지만 범용 정답은 아님
```

## 리롤 운이 지나치게 중요

대응:

- 카드 핀
- 무료 웨이브 갱신
- 보스 전 선택 보상
- 판매 100% 환불

- Lv.1~5만 우선 구현
- 설치 한도 3~7
- 1~3티어 상점 확률

- 카드 10개
- 리롤
- 카드 핀

- 1성→2성
- 2성→3성

- Stage/Wave
- 남은 시간
- 돈

이 범위로 경제 선택과 조합 재미를 먼저 검증한다.

# 20. 최종 규칙 요약

1. 한 번의 상점에는 장비 카드 10개가 나온다.
2. 웨이브마다 무료 갱신 1회가 제공된다.
3. 리롤 기본 비용은 `$8`이고 같은 준비 단계에서 증가한다.
4. 플레이어 레벨은 1~10이다.
5. 레벨은 상점 티어 확률과 설치 한도를 올린다.
6. 장비 티어는 1~5이며 장비마다 고정된다.
7. 같은 장비 3개를 합치면 2성이다.
8. 같은 2성 3개를 합치면 3성이다.
9. 3성 하나에는 1성 장비 9개가 필요하다.
10. 설치하지 않은 벤치 장비도 합성에 사용된다.
11. 요청 하나를 완료하면 기본 `$1`을 번다.
12. 돈은 장비 구매, 레벨업, 리롤에 사용한다.
13. 처리 RPM은 타워디펜스의 공격력에 해당한다.
14. 처리 RPM뿐 아니라 Queue와 지연도 함께 중요하다.
15. 고티어 1성보다 저티어 3성이 더 효율적인 상황을 만든다.
