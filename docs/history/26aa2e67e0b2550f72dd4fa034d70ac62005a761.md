## 작업 배경

직전 구현에서 Azure Portal 형태의 검은 헤더, 좌측 사이드바, 이모지 중심 아이콘이 추가되면서 기존의 밝은 보드 중심 디자인과 게임성이 훼손됐다. 동시에 20종 장비, 플레이어 레벨, 합성, 증강, 점검 패시브 기획이 일부 코드와 문서에 서로 다른 값으로 남아 있었다.

이번 작업은 첫 번째 UI 레퍼런스를 기준으로 화면을 다시 구성하고, 확정된 장비·레벨·점검 규칙을 실제 시뮬레이션과 상태 관리에 연결하는 것을 목표로 했다.

## 요구사항

- 좌측 사이드바와 포털 검색 헤더 제거
- 밝은 Stage/Wave HUD, 중앙 보드, 우측 상점, 하단 보유 장비 구조 복구
- 텍스트가 카드 밖으로 침범하지 않도록 오버플로 수정
- 20종 장비와 5개 티어 가격 적용
- 레벨 1~10 상점 확률과 XP 표 적용
- 레벨업 시 LINK 또는 BOARD 확장 선택
- 8칸 보유 장비와 동일 장비 3개 자동 합성
- 역할별 증강과 2성 5%, 3성 15% 레어 확률
- 긴급점검, 연장점검, 추가점검 구현
- 요청 → 서버 → DB → 응답 완료까지 성공 판정
- 보드 자유 확대·이동과 레벨별 자동 화면 맞춤

## 주요 설계 결정

### UI

- React UI를 `infra-main + shop-dock` 2열 구조로 단순화했다.
- 이모지 대신 코드 기반 SVG 장비 아이콘을 사용했다.
- 상점 카드와 인벤토리 카드는 고정 높이, 말줄임, line clamp로 내부 경계를 보장한다.
- Phaser 캔버스는 `RESIZE` 모드로 보드 영역 전체를 채운다.

### 경제와 레벨

- 시작 Credits는 240, 상점은 5칸, 리롤은 2, XP 4개 구매는 4 Credits다.
- 첫 상점만 최소 경로 구성을 위해 EC2와 RDS를 함께 고정 제공한다.
- 레벨업마다 남아 있는 BOARD/LINK 확장 슬롯 수 안에서 선택 보상을 생성한다.
- BOARD와 LINK가 모두 최대일 때 선택 불가능한 팝업이 남지 않도록 상한을 둔다.

### 장비와 성능

- 서버, DB, 로드밸런서는 보드에 직접 배치한다.
- Queue, Cache, Security, Storage 장비는 현재 패시브 성능 보정으로 처리한다.
- 성급, 티어, 증강은 서버·DB 동시성, Queue, 처리 시간, 응답 시간에 반영된다.
- 배치 장비가 합성 재료에 포함되면 합성 결과가 기존 역할과 위치를 우선 승계한다.

### 점검

- 최초 준비 60초, 정기점검 25초, 긴급점검 15초로 분리했다.
- 연장점검은 정기점검에 10초를 누적한다.
- 추가점검은 긴급점검 횟수와 정기점검 시간을 함께 늘린다.

## 알려진 제한사항

- 현재 실제 플레이 캠페인은 Stage 1만 완성되어 있다.
