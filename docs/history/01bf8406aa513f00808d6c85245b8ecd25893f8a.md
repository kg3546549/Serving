## 작업 배경

첫 번째 레퍼런스의 보드 중심 구조는 복구됐지만 화면에 설명 문장과 카드가 지나치게 많아 웹 관리 페이지처럼 보였다. 보드 카메라는 활성 영역을 벗어나 멀리 이동할 수 있었고 구매, 선택, 배치, 링크 연결의 게임 피드백도 부족했다.

현재 프로젝트는 이미 Phaser 3.90을 사용하고 있으므로 별도 DOM 애니메이션 라이브러리나 다른 웹게임 엔진을 추가하지 않고 Phaser의 Camera, Tween, Particle, WebGL FX 기능을 활용하기로 했다.

## 요구사항

- 화면의 설명 문장을 줄이고 전투 판단 정보만 상시 표시
- 상세 설명은 우클릭으로 확인
- 웹 페이지가 아니라 게임 HUD처럼 보이는 화면
- 클릭, 배치, 링크 연결, 패킷 이동에 애니메이션과 VFX 적용
- 자체 DOM 애니메이션보다 웹게임 엔진 기능 사용
- 보드 카메라가 무한히 이동하지 않도록 제한
- 제한된 영역에서 실제 패킷이 이동하는 아키텍처 보드 표현
- 변경 내용을 상세 커밋 메시지와 SHA 이력 문서로 관리

### Phaser 엔진 활용

- Camera `setBounds`: 활성 보드와 viewport에 맞는 이동 경계

- Particle Emitter: 배치 스파크, 선택 파편, 링크 도착, 패킷 트레일
- WebGL Glow: 패킷과 링크 펄스 강조

## 알려진 제한사항

- 패킷 VFX는 실제 웨이브가 시작된 뒤 표시되므로 준비 단계에서는 확인할 수 없다.
- 독립 보드 노드가 아닌 패시브 장비는 배치 VFX 대상이 아니다.
- Phaser 청크의 500kB 초과 빌드 경고가 남아 있다.
- 모바일 핀치 입력은 아직 지원하지 않는다.
