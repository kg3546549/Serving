## 2. 단계별 상세 개발 계획

### 🚀 단계 1: Phaser 3 기반 격자 및 카메라 조작계 구현
* **개발 순서**: 1
* **구현할 기능**:
  - Phaser Scene 초기화 및 기본 해상도(1200×720) 설정
  - 플레이어 레벨에 맞춰 가변 격자(7×4, 10×5, 13×6)가 그려지는 타일 렌더러 구현
  - 마우스 휠을 통한 줌인/줌아웃 및 빈 화면 좌클릭 드래그를 이용한 맵 스크롤 제어 구현
  - `R`키 입력 시 카메라 배율과 위치를 격자 중심부로 리셋하는 컨트롤러 구축
* **필요한 이미지**: 그리드용 격자 패턴 이미지 리소스
* **필요한 사운드**: 없음
* **완성 기준**:
  - 화면상에 격자판이 7×4 크기로 올바르게 정렬되어 렌더링되어야 함
  - 마우스 휠 스크롤과 마우스 드래그로 화면이 부드럽게 확대/축소 및 이동해야 함
* **확인 방법**:
  - 로컬 브라우저 구동 후 보드 위에서 마우스 드래그 및 휠을 스크롤하여 오작동 여부 점검
  - `R`키를 누르면 카메라가 즉시 초기 좌표로 원복하는지 검사

---

### 📦 단계 2: React HUD 구성 및 장비 드래그앤드롭 배치 시스템
* **개발 순서**: 2
* **구현할 기능**:
  - React 19와 Zustand를 연동하여 상단 HUD(점수, 서비스 HP, 재화), 우측 상점 패널, 하단 인벤토리 도크를 렌더링
  - 인벤토리나 상점 카드에서 마우스로 장비를 선택하여 보드의 원하는 격자 좌표에 드롭 시 해당 좌표에 장비 배치 노드를 생성하는 기능
  - 보드에 이미 배치된 장비를 좌클릭 드래그하여 다른 격자 좌표로 이동시키는 기능
* **필요한 이미지**: 서버, 로드밸런서, 데이터베이스 기기의 SVG 아이콘 리소스
* **필요한 사운드**: 장비 집어올릴 때(Click) 및 내려놓을 때(Place)의 사운드
* **완성 기준**:
  - 상점에서 클릭한 장비 카드가 마우스 포인터를 따라 움직이며, 보드 위의 그리드에 가져다 대면 스냅(Snap) 처리가 이루어지고, 드롭했을 때 노드 렌더링이 완료되어야 함
* **확인 방법**:
  - `EC2` 및 `RDS` 등의 카드를 드래그하여 그리드에 올려놓아 그리드 중심에 정확히 위치하는지 확인
  - 이미 배치된 기기를 드래그하여 다른 빈 셀로 움직였을 때 좌표가 갱신되는지 테스트

---

### 🔗 단계 3: 장비 간 Manhattan Distance 검증 및 링크 연결선 시스템
* **개발 순서**: 3
* **구현할 기능**:
  - `Shift + 좌클릭 드래그` 또는 `우클릭 드래그`로 한 노드에서 다른 노드로 드래그했을 때 연결선(Link)을 그리는 핸들러 구현
  - 출발 노드와 도착 노드 간의 맨해튼 거리(가로 격자 수 + 세로 격자 수) 계산 로직 설계
  - 연결 조건 제약 검사: 허용된 포트 사양(Ingress → Server, Server → DB, DB → Server, Server → Egress)에 맞는 기기 간만 연결되도록 필터링
  - 현재 링크 레벨이 허용하는 링크 예산 초과 시 연결 생성을 차단하는 유효성 로직 구현
* **필요한 이미지**: 링크를 표시할 단색 및 점선 그래픽 라인, 방향 가이드 화살표
* **필요한 사운드**: 링크 연결 성공음, 연결 조건 위반 시 경고음
* **완성 기준**:
  - 올바른 노드 간의 드래그 조작 시 파란색(트래픽), 노란색(데이터) 선이 나타나고 연결이 고정되어야 함
  - 잘못된 경로(예: DB에서 Ingress로 직접 연결 등) 시도 시 연결이 불허되고 경고가 출력되어야 함
* **확인 방법**:
  - `Traffic Ingress`에서 `EC2` 서버 노드로 드래그하여 파란색 연결선이 제대로 가설되는지 테스트
  - 기기 간 거리를 늘려 링크 제한 수치를 넘겼을 때 차단 팝업이 노출되는지 점검

---

### ⚙️ 단계 4: 시뮬레이션 Tick 루프 및 패킷 이동 연출
* **개발 순서**: 4
* **구현할 기능**:
  - 시뮬레이션 '서비스 개시' 클릭 시 실시간 시뮬레이션 루프(`setInterval` 혹은 Phaser `Timer`) 작동
  - Zustand 상태의 성능 지표를 기반으로 트래픽 발생 주기마다 Ingress에서 요청 패킷을 생성
  - 패킷이 지정된 경로(연결선)를 따라 순차적으로 다음 노드로 등속 이동하도록 Phaser Tween 애니메이션 구성
  - 노드의 대기열(Queue) 상태를 시각화하기 위해 기기 상단에 큐 텍스트 및 게이지바 렌더링
  - 처리 성공 시 Egress로 도달하여 코인 획득, 시간 초과/큐 폭발 시 패킷이 소멸하며 서비스 HP 감소 처리
* **필요한 이미지**: 패킷용 원형 빛 리소스
* **필요한 사운드**: 서비스 가동 중 배경음, 처리 성공음, 요청 실패 시의 경보음
* **완성 기준**:
  - 웨이브가 가동되면 패킷이 Ingress에서 출발하여 서버를 거쳐 DB를 다녀온 후 Egress로 안전하게 복귀하는 흐름이 시각적으로 연출되어야 함
* **확인 방법**:
  - 웨이브 시작 버튼을 눌러 패킷들의 연쇄 이동 연출을 관찰하고, 대기열이 가득 찼을 때 기기 위에 빨간 대기열 경고가 누적되는지 검증

---

### 💎 단계 5: Zustand 스토어 기반 상점 리롤/합성 및 증강 기능
* **개발 순서**: 5
* **구현할 기능**:
  - Zustand 스토어에서 Credits를 관리하여 상점 리롤 시 2 Credits 차감 및 레벨 확률에 기반해 아이템 리스트 갱신
  - 인벤토리 및 보드를 감시하여 이름이 같은 장비가 3개 감지되면 즉시 하나의 상위 성급(2성/3성) 장비로 병합하는 자동 합성 로직 구현
  - 합성 성공 시 3개의 랜덤 증강 옵션 카드 팝업을 띄우고, 선택에 따라 해당 장비 인스턴스의 성능 팩터(처리 속도 향상, 대기큐 증설 등)를 갱신하는 시스템 구축
* **필요한 이미지**: 업그레이드 별 표시(★) 이미지, 카드 증강 UI 일러스트
* **필요한 사운드**: 합성 성공 팡파르음, 카드 선택 버튼음
* **완성 기준**:
  - 동일한 장비 3개를 모으자마자 소리 효과와 함께 하나의 강화된 장비로 합쳐지고, 능력치에 증강 효과가 누적 반영되어야 함
* **확인 방법**:
  - 1성 장비 3개를 연속 구매하여 2성으로 병합되는 과정 및 증강 옵션 적용 후 툴팁에 능력치 상승분이 기재되는지 검증

## 3. 개발 진행 기준 (Definition of Done)
1. **기능 구현 검증**: 각 개발 단계 완료 시 마일스톤 완성 기준의 동작이 로컬 웹 브라우저(`http://localhost:5173`) 상에서 깨짐 없이 100% 정상 구동되어야 함.
2. **테스트 통과**: 핵심 연출 외의 모든 로직(Manhattan 거리 계산, 링크 포트 제약 조건 검증, 상점 가챠 확률 배분, 합성 판정 알고리즘 등)에 대해 작성된 Vitest 유닛 테스트 코드(`npm test`)가 에러 없이 모두 통과(GREEN)해야 함.
